# Consensus model

MOSAIC uses the narrowest consensus mechanism that fits each value:

- `strict_eq` compares bounded, objective GitHub facts and normalized source snapshots byte-for-byte.
- `prompt_comparative` is used for semantic contribution capsules whose prose is not itself economic.
- `run_nondet_unsafe` is used only for the final structured mission judgment. Leader and validator independently produce and normalize `terminal_objective_status`, `claimant_outcome`, and the complete registered-wallet role map. Any mismatch, malformed schema, exception, omitted wallet, or extra wallet rejects resolution. Rationale is a non-economic leader explanation.
- Allocation is deterministic Python contract code. Validators never choose percentages, weights, rounding, or recipients.

Terminal objective status describes the actual bounded target-state snapshot. Claimant outcome describes only causal impact attributable to eligible sealed MOSAIC portfolios; unregistered work can explain terminal success but cannot receive funds or create a role.
